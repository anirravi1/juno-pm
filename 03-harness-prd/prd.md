## Problem & user

RocketShip PMs need this handled: Juno is an assistant that helps me identify issues associated with the features I own and turns them into a prioritized backlog, points out risks, impact to feature health and highlights related historical issues that were resolved.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

Sources to include are the following:
1. Webex spaces - especially the ASK spaces where customer success managers report issues
2. JIRA tickets - any bugs reported for specific features. Also, use tasks, stories or epics under the portfolio feature to identify related issues or ongoing work that might be associated with the prioritized issues.
3. Prioritized roadmap for the current quarter and backlog 
4. Confluence pages with feature information

**How fresh must it be**

Use latest information from all the mentioned sources to prioritize the issues.
When a source is unreachable, troubleshoot and fix any version, access or authorization issue. Re-run the model to generate the latest prioritized list of issues.

## 02 Tools · System Capabilities

**The verb list**

Webex spaces and messages, JIRA, Confluence

**Deliberate omissions**

BEMS tickets - every BEMS ticket has a Webex space associated with it. So, the issues will not be missed and/or duplicated.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

An attempt is successful if the model is able to parse through all the provided sources to generate the output.
If there is any failure with access to a specific source, re-run after troubleshooting and fixing the issue. 
If required, notify me if any source needs my authorization.

**Latency and cost target**

Run the model once a day every morning or if the user requests for the latest output.
Attempt to generate the output within 5 minutes of running the model.

## 04 Memory · Data Requirements

**What persists, at what scope**

All output results from each session should persist. 
History of each feature and issues associated with the features should persist. 
Only the customer name can persist in the memory, but no other customer information should.

**Expiry and write rules**

The issues and information related to the issues should never expire.
The prioritization of the issues can expiry after 3 months.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Read - ability to read from all provided sources
Draft - expected output related to prioritization of issues as well as recommendations and timelines
Write - write the new prioritization into JIRA after getting confirmation from me
Send - do not send any information to any of the communication tools, especially Webex spaces

## 06 Verification · AI Testing & Measurement

**The check before output ships**

The prioritization of issues is always checked and confirmed by me before it is published to JIRA. But any user using this model should be able to generate an output.

**Failure behaviour**

When the check fails, the model should be able to generate the output but it will be restricted from publishing anywhere.
